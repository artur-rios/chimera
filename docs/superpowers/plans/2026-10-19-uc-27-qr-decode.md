# UC-27 QR Decode Implementation Plan

**Goal:** Decode supported local images through a shared bounded QR decoder.
**Spec:** docs/superpowers/specs/2026-10-19-uc-27-qr-decode-design.md
**Branch:** feature/uc-27-qr-decode
**Issue:** #28

## Task 1: Shared decoder and core service

Write and observe failing tests for PNG/JPEG/BMP QR vectors, Unicode, rotated
symbols, corrupt/unsupported/no-code inputs, encoded-byte/pixel/output budgets,
and core success/failure mappings without sensitive diagnostics. Promote
zxing2 0.2.4 to utility dependencies. Implement the decoder, immutable result,
typed exception, service/request/output and operation-service alias. Export
public types. Match the contracts in the design. Run utility/core tests.

## Task 2: GUI adapter

Write and observe failing widget tests for locale success, cancellation,
picker/decode/copy/save failures, resource handling, input/result cleanup,
keyboard/focus and semantics. Add qr_decode_page.dart and injection into
app.dart/router.dart. Route is /qr/decode, widget keys use qr-decode-*.
Use the service contract in the design and the shared localized catalog keys.
Run GUI tests. Do not modify localization catalogs or CLI files.

## Task 3: CLI and localization

Write failing CLI tests for binary file/stdin, all source/option validation,
localized safe failures, JSON, output save and cleanup. Implement qr decode
with bounded reads and transactional writes using existing runner conventions.
Add complete English/pt-BR keys for GUI and CLI. Run CLI/l10n tests.

## Task 4: Supported targets and review

Extend native integration, browser and Safari smoke coverage. Update the README
backlog, usage and accessibility evidence. Run formatting, analysis, boundaries
and the complete exact test:all gate. Request independent review, fix findings,
rerun affected and complete gates if changed, open PR with Closes #28, wait for
required CI, merge, verify issue/project Done, delete branch, sync develop.

## Gate self-check

Main and AF-01/AF-02 are mapped in the design; all FR references exist; each
implementation task begins with tests. Tasks share only the documented core
contract; GUI owns app/router/page/widget files; CLI owns runner/l10n; utility
owns exports/service. Target integration is sequenced after those tasks.
